# Calibrated Outcome Maker (Solana)

Rust port of the market maker in `../evm`, written with Anchor. Same pricing, same record rules, same inventory controls; the account model is Solana's.

## Files

| Path | What it is |
| --- | --- |
| `programs/calibrated-outcome-maker/src/math.rs` | Pure pricing arithmetic: floor, quote, exact-input price, improvement test. No account plumbing, so clients can reproduce a quote offchain from account data. Unit and property tests live here. |
| `programs/calibrated-outcome-maker/src/state.rs` | Account layouts: `Maker` (roles, quote signer and record rules), `Market` (one per outcome mint), `CalibrationRecord` (one per model id), `CollateralMarker` (keeps a collateral mint from ever becoming an outcome mint). All are program derived addresses (PDAs). Also the `QuoteParams` and `SignedQuote` instruction arguments. |
| `programs/calibrated-outcome-maker/src/instructions/` | `admin.rs` (init maker, set market, pause, quote parameters singly or in a batch), `calibration.rs` (publish a record), `liquidity.rs` (deposit, withdraw), `swap.rs` (exact-input swap from stored parameters or from a co-signed quote), `views.rs` (floor, quote, improvement test, amount out). |
| `programs/calibrated-outcome-maker/src/error.rs` | Error names match the Solidity contract one for one. |
| `programs/calibrated-outcome-maker/tests/maker.rs` | Integration tests against the compiled program in LiteSVM. |
| `idl/calibrated_outcome_maker.json` | Anchor interface definition language (IDL) file generated by `anchor build`, for clients. |

## Build and test

Built with anchor-cli 1.0.0, anchor-lang 1.2.2, solana-cli 3.1.12 and Rust 1.89.0 as of 2026-10-29.

```
anchor build --ignore-keys   # compiles the program to target/deploy and regenerates the IDL
cargo test                   # unit and property tests, then the LiteSVM integration tests
cargo fmt --all -- --check && cargo clippy --all-targets
```

`--ignore-keys` is needed on a fresh clone: the program keypair is not committed, so `anchor build` generates a new one and would otherwise stop on the mismatch with the id in `lib.rs`. The tests load the program at the declared id, so the mismatch does not matter until deployment, at which point `anchor keys sync` rewrites the id to your keypair. `cargo test` needs `target/deploy/calibrated_outcome_maker.so` from the build step. `anchor test` is not used: it launches a local validator, which nothing here needs.

## How the Solidity design maps onto Solana

- Markets, records and the collateral marker are PDAs seeded by the maker and a mint or model id, so lookups need no mapping storage and an outcome mint cannot be configured twice (the second `set_market` fails at account creation).
- Vaults are the associated token accounts of the market PDA. Collateral is therefore held per market, not per maker: `InsufficientInventory` on a sale refers to that market's collateral vault.
- Views (`spread_floor_bps`, `quote_bps`, `improves_book`, `get_amount_out`) are instructions that return their result as return data. Simulate the transaction and read it, or recompute with `math` from the account data.
- A missing record reports `NoCalibration`: the record account is passed unchecked and read manually rather than required to exist.
- Direction of a swap is taken from the mints of the taker's source and destination token accounts. The destination can be any token account of the output mint.
- SPL Token only. Token-2022 mints with transfer fees or transfer hooks are not supported, which matches the fee-on-transfer exclusion in the Solidity version.
- Mint decimals are capped at 18 (the Solidity version allows 36) so that every intermediate product fits in u128; the arithmetic is checked regardless.
- Position is an i128 ledger of fills, deposits and withdrawals. Tokens minted or transferred straight into a vault are deliverable but uncounted, as in Solidity.
- Reentrancy is not a concern: the only cross-program invocations are to the token program, and Solana forbids re-entering this program from there. Position is still written before the transfers.

## Two quote paths, one settlement

`swap` prices from the market's stored parameters. `swap_with_quote` takes a `SignedQuote` (`bid_bps`, `ask_bps`, `max_outcome_out`, `max_outcome_in`, `expiry`) in the instruction data and requires the maker's `quote_signer` key to co-sign the transaction. Both end in the same settlement code: position written, two `transfer_checked` calls, one event.

The co-signer model replaces the EVM's EIP-712 (Ethereum Improvement Proposal 712) signature. Because the engine signs the whole transaction, the quote is bound to this exact taker, amount, slot range and accounts, so there is nothing to replay and no nonce account to rent. The cost is one more signature per fill (the taker and the engine both sign, or the engine builds and signs the transaction and the taker adds its signature) and one key for the engine to hold online. An alternative that keeps the taker's transaction single-signer would verify an ed25519 signature over the quote through the ed25519 program and instructions sysvar, plus a nonce PDA per quote; that is heavier per fill and is not implemented here.

What the program checks before honouring the engine's price, in order: the co-signer is `maker.quote_signer`, the quote has not expired, the record is present and fresh, `ask <= 10 000`, `ask >= bid`, `ask - bid >= floor`, then the same exact-input arithmetic, inventory limit and vault balance checks as `swap`, then the quote's size cap in the direction of the fill. A maker initialised with the default public key as `quote_signer` has the path disabled: no key can sign as it.

`set_quote_params_batch` takes the market accounts as remaining accounts, one per entry of `params`, and applies the same validation as `set_quote_params` to each. Each market is checked to belong to the maker and to be writable.

## What the tests cover

Unit and property tests (`math.rs`, 11 unit tests and 3 property tests at 512 cases as of 2026-10-29):

- Floor from the paper's numbers (calibration examples as of June 2026): alpha 0.149 and phi 0.15 give 447 bps; alpha 0.354 gives 1062 bps; rounding is upward; a floor above 10 000 bps is refused and exactly 10 000 is allowed.
- Quote at both clamp bounds, with a full-width spread, with skew moving the mid against the held side with the spread preserved, and refusal when the skew across the full limit exceeds the spread.
- Exact-input price in both directions; zero input, zero ask, zero output and inventory limit rejections, with the limit check running before the zero output check.
- Round trip of the full limit at the skew boundary cannot return the full size.
- Property tests: the quote never narrows below the floor or the operator spread and never exceeds 10 000; the taker never fills inside the posted quote; no successful fill leaves |position| above the limit.

Integration tests (`tests/maker.rs`, 24 tests as of 2026-10-29):

- Setup state including the stored quote signer; zero attester refused; repeated market, self pair, token-role collisions and 19-decimal mints refused; a second market sharing a collateral accepted.
- Only the operator sets parameters, only the attester sets records; basis points out of range refused.
- Record rejections with the exact error: stale, sample too small, future `measured_at`, resolution after measurement, resolution at the training cutoff; one second after the cutoff accepted; URI length bound; in-place replacement updates the floor.
- Floor 447 and quote (5777, 6224) through return data; a floor above range refused from the floor view, the quote, `get_amount_out` and `swap`; a market whose model has no record reports `NoCalibration`; staleness boundary exact to the second.
- `get_amount_out` equals what `swap` delivers in both directions; balances and position move accordingly.
- Zero input, slippage, expired deadline, zero output, empty collateral vault, inactive market.
- Inventory limit in both directions to the base unit; deposit and withdraw move position for the outcome mint only.
- Skew guard, then a sell-then-buy round trip at the boundary that cannot extract collateral.
- Two-sided improvement including the strict boundary.
- Signed quotes: fills in both directions at the signed price with position moving accordingly; 446 bps, a crossed quote and an ask above one refused, exactly 447 accepted; the floor following a record change to 1062; expiry refused; an impostor co-signer refused; a stale record refusing signed quotes; size caps exact to the base unit in both directions; the inventory limit binding regardless of the quote; a maker with no signer refusing the path while `swap` still works.
- Batch: two markets set in one instruction; length mismatch, bad basis points, a non-market account and a non-operator refused with nothing changed.

## Known limitations

- Self-attested calibration, immutable roles, linear pricing, ledger position: the same as the Solidity version.
- One maker per operator key (the maker PDA is seeded by the operator).
- Parameter updates are visible before they land and can be traded against in the same slot. Signed quotes do not have this problem because the price never passes through account state.
- A compromised `quote_signer` key can quote at the floor until the operator pauses the market; it cannot quote inside it. The signer is set at `init_maker` and there is no rotation instruction.
- Not audited. Do not deploy with real funds.
